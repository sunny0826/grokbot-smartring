# GrokBot 显示管线调优经验教训（SmartRing-Plus / ESP32-S3 / ST77916）

> 2026-10-16 重力动画调试实录。症状演化：卡顿 → 手感慢 → 拖影乱码 → 静止锯齿 → 运动阶梯锯齿。
> 每个症状一层根因，修表层会让下一层暴露出来。按"先测量、再归因、最后修"的顺序推进才没有走回头路。

## 硬件/管线事实（重测很贵，直接引用）

- 屏幕：ST77916，360×360 QSPI 40MHz，RGB565，TE 脚接 GPIO38（板级已布线，BSP 默认未用）
- LVGL 适配器：esp_lvgl_adapter，PARTIAL 渲染 + 40 行条带缓冲（整屏单块 flush 需 259KB 内部 RAM 反弹缓冲，会 NO_MEM）
- 面板 TE 输出 ~62Hz；flush 若与扫描不同步必撕裂
- PSRAM：顺序 u16 写 ~120ns/px，读改写 ~235ns/px；内部 RAM 快一个数量级
- **newlib 的 sqrtf/hypotf 是软实现（~100 周期/次）**，热路径禁用，用平方距离 + 泰勒近似 `(d²-1)/2 ≈ d-1`

## 分层根因与修法

### 1. 卡顿（49ms/帧）—— 数学库
热路径里的 hypotf 是元凶。所有覆盖率/距离判定改平方距离，编译优化开 PERF。

### 2. 拖影/乱码 —— 缓冲一致性
自维护脏矩形 + 原地覆盖画布时，失效区域必须覆盖"新位置 ∪ 旧位置"且在每份底层缓冲上都成立。
简单可靠的做法：**整幅画布失效**（`lv_obj_invalidate`），让 LVGL 自己同步。光栅化够快时（~10ms）整幅刷新在预算内。

### 3. 静止边缘锯齿 —— 覆盖率精度
- 1px 线性过渡带在亚像素移动时会在 565 灰阶间跳变
- 修：过渡带加宽到 2px + smoothstep 整形（`c*c*(3-2c)`）+ 混色四舍五入（截断会系统性偏暗）
- 注意包围盒 padding 要同步加大（1.5 → 2.5px），否则软边被裁掉

### 4. 运动撕裂 —— 帧同步
DMA 写显存和面板扫描不同步 → 边缘在撕裂线处错位成台阶。
修：屏幕初始化表加 `TEON(0x35, 0x00)`，显示注册改 `TEAR_AVOID_MODE_TE_SYNC`，TE 脚 GPIO38。
写入从 TE 沿开始且快于扫描束（10.2ms < 16.1ms），物理上不可能撕裂。

### 5. 运动大阶梯 —— 帧率崩塌（最难找的一层）
两个叠加问题：
1. **适配器原版 TE flush 每个 40 行条带都等一次 vsync**：一帧 8 条带 = 8 × 16.1ms ≈ 130ms/帧。
   补丁（`components/esp_lvgl_adapter/.../lvgl_bridge_v9.c`）：TE_SYNC 单缓冲下 flush 严格串行，
   用块序号只在每帧**首个条带**等 vsync，其余条带背靠背传输，依然无撕裂。
2. **条带缓冲在 PSRAM**：每块要 PSRAM→PSRAM 拷贝 + 字节交换 + 反弹到内部 RAM，每块 ~6ms。
   改 `use_psram=false`（内部 RAM 条带，2×28.8KB）：字节交换在内部 RAM 做、DMA 直通免反弹拷贝，
   每块 ~2ms。整帧管线 58ms → 35ms（28fps）。

### 6. 物理速度失真 —— 固定 dt
帧率被 TE 门控后会随管线耗时浮动。固定 dt 在帧率不符时产生快慢失真。
修：用 `esp_timer` 实测帧间隔做 dt，钳制 [4ms, 50ms]。

## 诊断手法（可复用）

- **串口日志计数**：每 N 次回调打一条带时间戳的日志，日志间隔 ÷ N = 真实帧周期。比 FPS_STATS 更直接
- **GPIO 轮询验证信号存在性**：怀疑 TE 没到？`gpio_get_level` 紧循环 500ms 数上升沿（31 个 = 62Hz 确认）
- **分段计时**：`esp_timer_get_time()` 包住光栅/清屏/拷贝各段，每 5 秒报均值+峰值
- **改 BSP/适配器**：组件本地化（拷到 `components/` + 从 `idf_component.yml` 移除注册表依赖），
  否则 managed_components 里的修改会被覆盖且污染其他工程

## 当前性能预算（实测）

| 阶段 | 耗时 |
|---|---|
| 光栅化（含清屏） | ~12.7ms 均值 / 19.7ms 峰值 |
| LVGL 拷贝+交换+DMA（内部 RAM 条带） | ~16ms |
| TE 等待 | ≤16.1ms（与上帧流水重叠） |
| **整帧** | **~35ms ≈ 28fps** |

物理参数：ACC=2.4、DAMP=0.9、RESTIT=0.42、PMAX=0.52、SCALE=100px、CANVAS=320。
