# 圆屏动画优化补充方案

> 后续实施状态：[云端流程与局部刷新已实施；含实机对照结果](../implementation/overall-throughput.md)。下文保留当时的分析与方案。
2026-10-17。补充到[语音延迟方案](voice-latency.md)。本轮核对源码与历史验证记录，仅形成方案，未修改或烧录固件。用户尚未指定更偏向流畅度还是语音反馈，暂按两者都覆盖。

## 已定位的实现问题

| 事实 | 影响与边界 |
|---|---|
| `main.cpp:607` 的角色回调为 16 ms；当前 sdkconfig 和 build/config 均为 `CONFIG_LV_DEF_REFR_PERIOD=33`；本地 LVGL 用该值创建显示刷新 timer | 计算节奏与显示刷新节奏不一致，16 ms timer 不能证明屏幕有 60 fps。所查主路径没有覆盖刷新周期；需测真实刷新/DMA完成间隔 |
| `main.cpp:382` 每帧 invalidate 整块 320×320 canvas；带装饰的姿态还会完整清除 framebuffer | 已有局部清除不等于局部显示传输。旧方案曾发生残影，因此不能直接缩小 invalidate 区域，必须覆盖旧、新角色及装饰、抗锯齿边界 |
| 语音/配网页面激活时 `frame_cb` 提前返回；语音根容器为不透明全屏 | 角色动画暂停且被遮住。不能简单删除 early return：会在看不见的底层继续绘制，增加负载 |
| `voice_ui.cpp:329` 每 100 ms 取状态，音量条使用 `LV_ANIM_OFF`，录音点每 500 ms 切两档透明度 | 音量变化是跳变，录音提示是硬闪烁；状态进入/离开基本是直接切换 |
| `bot_states.cpp` 的待机轮播自行播放 Thinking、Notify、Happy 等姿态 | 这些姿态当前并不代表真实 Bot 状态；复用为语音反馈时应明确归属，避免空闲时看起来像正在处理任务 |
| `home_controls.cpp` 已实现短点唤出、10秒不触摸隐藏 | 保留用户已有交互规则；优化过渡不应改变首次点击、长按录音、滑动换角色语义 |
| `main.cpp:119` 将 dt 限制为最高 50 ms，并用它累加动画时间 | 若帧间隔持续超过 50 ms，动画时间会落后真实时间。需区分视觉时钟和物理积分；不要直接放开物理大步长 |

[既有显示排障记录](../display-pipeline-notes.md)记载某次固件回调约 15.8 fps，且当时没有验证连接 Wi-Fi/TLS 的负载。它不是本次当前设备测量；注释中的约 60 fps、历史 28 fps 都不能当成现在已达到的性能。

## 体验方案：让每个动作都有明确含义

| 场景 | 建议动画 | 完成/取消条件 |
|---|---|---|
| 待机 | 保留当前角色皮肤、轻微呼吸、眨眼与倾斜互动；减少高频大幅装饰 | 真实语音状态优先，不播放会被误解成任务通知的假提示 |
| 录音 | 平滑音量条或低成本小波形；快速跟随声音、稍慢回落；保留“松开发送” | 取真实音频峰值，不用随机跳动冒充麦克风输入；松手或取消立即停止 |
| 上传/转写 | 小范围循环动效，配“上传中/转写中” | 由 VoicePhase 切换；不显示无法计算的百分比 |
| 等待毛线/已领取 | 等待时缓慢呼吸；claimed 后再用已有三点 Thinking 姿态 | 区分“排队”和“已接单”，动画不重新触发 Bot，也不产生网络请求 |
| 回复到达 | 轻微弹出一次的 Notify 提示，随后稳定；前台首屏淡入 | 不持续闪烁，不自动标记已读，后台不抢占正在进行的操作 |
| 错误/断网 | 停止工作循环，稳定显示状态与重试入口 | 不用持续转圈掩盖失败；按钮即时响应 |
| 主页控件 | 显示约120–160 ms、隐藏约160–220 ms的短过渡，作为初始设计参数 | 输入命中随逻辑可见性管理；隐藏控件不能截获点击；首次唤醒不触发录音 |

首轮优先用现有语音页面的小范围动效，成本低，也不会把背景角色每帧重画。角色进入语音页面是第二阶段：由一个呈现控制器决定当前姿态和可见区域，复用已有 `poseFor` 与皮肤绘制，避免首页轮播和语音状态各自争用画布。动画只消费状态快照，不能更改任务状态或领取权限。

## 流畅度方案与顺序

1. **先建立当前设备基线。** 在主页、三种皮肤/装饰、录音、上传、等待、回复页和配网下，分别记录 callback间隔、光栅化、LVGL copy/swap、首条TE等待、所有DMA完成及输入反馈；Wi-Fi/TLS连接和语音同时工作也测。现有 raster日志没有覆盖全部显示耗时；“每300帧”也不能写死为“每5秒”。不为取串口日志擅自重置设备。
2. **统一实际可维持的节奏。** 初始目标是稳定约30 fps，先控制长帧和抖动；若实测预算允许再比较更高帧率。以实际显示完成为证，不能仅把 timer 改为16 ms就称60 fps。视觉循环按真实时间推进；物理运动用有上限的子步积分，恢复页面时重置/同步时间，避免大跳或持续慢动作。
3. **平滑局部反馈。** 状态刷新保留事件/快照语义，动效由LVGL动画或轻量插值推进；音量取最新真实值，加快升慢降包络。只在文字变化时更新 label，避免10Hz重复设置相同文案。隐藏页面停止无用动画，退出时清理动画引用。
4. **有证据后缩小重绘。** 先记录每帧脏区域和实际传输字节；为旧/新姿态、皮卡丘耳朵、木木枭翅膀、圆环、徽标、Zzz与抗锯齿外沿计算正确联合范围。对照全量渲染输出，换皮肤、旋转、遮挡恢复也无残影后才采用局部更新；装饰复杂时允许全量回退。
5. **保持已修复的显示资源约束。** 当前是单个40行、28,800字节的内部DMA缓冲，每帧首条带等TE，其余条带等待DMA完成后复用。不得直接恢复259,200字节整屏内部缓冲或未经测量加双缓冲；历史上已发生内部连续内存不足。若需改适配器，单独做内存、TE与并发负载验证。

[LVGL官方显示说明](https://lvgl.io/docs/open/9.3/details/main-modules/display/setup)区分部分渲染和缓冲/flush完成；[动画说明](https://lvgl.io/docs/open/9.3/details/main-modules/animation)可用于实现局部插值。具体API以项目已锁定源码为准，不为动效升级框架。

## 如何验收

- 先展示可复核的动画预览，再用真实圆屏验证观感；浏览器或主机模拟不能证明ESP32帧率。
- 录音音量确实跟随声音，取消、松手、失败、返回和回复切换都不残留旧动画。
- 短点唤出、10秒隐藏、长按录音、滑动换皮肤、配网触摸、未读与翻页全部保持。
- 对照至少五段同条件测量，报告显示完成的帧间隔中位数/尾部、长帧数量、最大连续内部空闲内存及错误计数；连网录音时不发生音频丢失或动画抢占。
- 重绘优化逐帧对比像素/边界，实机确认无残影和明显撕裂。稳定30 fps是待验证目标，当前没有达成结论。

实施顺序建议：真实阶段文案和局部录音/等待反馈 → 帧时测量与节奏统一 → 控件短过渡及回复首屏 → 视测量结果决定角色共享呈现与局部重绘。动画改善等待体验，语音后端的30～40秒仍按主报告另行优化。
