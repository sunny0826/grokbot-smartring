- 固件 `0.11.0-partial-refresh`：收集绘图实际覆盖范围，清除旧范围，仅刷新新旧范围并集；换皮肤、页面遮挡后恢复时全清。视觉时钟按真实时间推进，物理运动分成不超过25ms的小步，仅超过250ms的停顿限制追赶。
- 第一阶段 `voice_bridge 0.3.1` 的进程预热、窄列查询、持久分段计时，以及语音阶段文案、平滑音量、等待/回复动效继续使用。

## 显示：同设备、同二进制的交错对照

固定 `three-skins-idle-v1` 墙钟轨迹，每段依次覆盖三皮肤；每段1秒热身和15秒测量，旧全屏/新局部路径共10段，每侧5段，按 AB、BA 交错。两侧保持相同亮度、40行内部DMA缓冲、首条带TE同步及编译设置。基准路径复现旧清屏算法，但不是两个完整历史固件的对照。

| 指标 | 旧全屏路径 | 新局部路径 |
|---|---:|---:|
| 完成帧率中位数 | 11.81 fps | 17.66 fps |
| 五段帧率范围 | 11.73–12.17 | 17.30–17.80 |
| 每完成帧传输字节中位数 | 204,800 B | 89,968 B |
| 各段完成间隔p50上界 | 82–83ms | 51–52ms |
| 各段完成间隔p95上界 | 102–115ms | 82–85ms |
| 失败帧 / TE超时 / 测试中断 | 0 / 0 / 0 | 0 / 0 / 0 |

该轨迹完成吞吐中位数提高 **49.48%**，每完成帧传输量减少 **56.07%**。帧率用 `(frames - 1) / 首次到末次完成的秒数` 计算，完成时间在末条带DMA确认之后。分位数为1ms桶上界；采集结果未进入溢出桶。工具已修正未来溢出桶输出为null，该修正已用目标SDK编译，不影响现有结果。

[原始采样](../analysis/voice-throughput-evidence/display-ab-raw.json) · [计算及基准固件SHA256](../analysis/voice-throughput-evidence/display-ab-summary.json)。`refresh_us` 含TE等待和条带间LVGL处理，不能当纯DMA时间；各模式的皮肤采样权重随帧率变化，不单独宣称CPU渲染加速。

基准在新物理时钟提取前构建，受控pose覆盖真实物理姿态，只证明重绘路径收益。**尚未达到30fps**；不能外推录音/TLS并发、全部姿态与触摸观感。新物理时钟另以主机行为检查和最终固件构建验证。

## 语音：云端更新后的五次真实请求

桌面控制仍不可用，因此使用已授权的原Bot语音链路送达任务更新指令；Bot回复确认保存并读回。随后用相同5.455秒合成测试WAV发起五次真实请求，每次均一次通知，网关各出现且只出现 `voice.claim → voice.reply`，无list/get_state、无手动领取回复。客户端都验证了预期回复与首屏VPG1/CRC。

服务端 stored→replied：**26.94、23.00、28.29、29.78、24.91秒**，中位 **26.94秒**。通知HTTP200记录→领取仍需11.91–15.05秒，领取→收到回复8.03–13.55秒。主要剩余等待在云端调度/执行阶段；没有云端内部计时，不能全部归于模型思考。

[五次分段结果和工具调用摘要](../analysis/voice-throughput-evidence/voice-current-five-runs.json)。这是当前流程五次验收，不是严格旧/新交错对照，不报告稳定语音加速比例，也不代表按键释放→实体首屏的耗时。原始音频、任务认证及其他私密数据未复制进仓库。

## 实现与正确性

选择图元写入边界收集，避免每帧扫描整张影子缓冲，也不新增约200KiB的全屏副本。collector在现有绘制循环内收集范围，按值传递Fb避免栈上指针逃逸；统一renderer管理旧范围，删除皮肤full-clear标志和main手算范围。

显示失败在整轮刷新内保持标记，失败轮不算成功FPS；在LVGL清空失效区域后的REFR_READY事件安排下一轮全屏恢复。保持原TE/DMA结构，没有引入未经验证的DMA通知超时。丢失DMA完成通知仍沿用原无限等待，未声称覆盖该故障。

验证：

- 2620帧逐像素全重绘/增量缓冲/模拟面板对照，三皮肤、七状态、切换、透明绘制、边界、reset；额外450帧固定轨迹核对旧算法。ASAN/UBSAN通过。
- 180帧真实LVGL合成对照：canvas偏移、透明叠层、隐藏恢复；首/中/末条带模拟失败后全屏修复。故障注入使用真实guard和LVGL，未在实体GPIO TE链路注入故障。
- 物理运动：100ms分步等价、15/60fps轨迹接近、长停顿上限、边界稳定和归中通过。
- 最新语音UI和配网UI真实LVGL回归通过；此前78项Python、语音核心检查通过，本轮未再改Python服务实现。
- 独立同模型只读设计与审查；无未修复的确定正确性缺陷。[最终审查](../analysis/voice-throughput-evidence/review.md)。

可复跑：`python3 firmware/grokbot/tools/check_render.py`；语音与配网分别运行 `check_voice_ui.py`、`check_wifi_ui.py`。实机基准只在构建时设 `MY_BOT_DISPLAY_BENCHMARK=ON`，采集工具为 `measure_display.py --port PORT --output PATH`；正式固件必须设OFF，默认无基准模块。

## 部署与边界

正式IDF 5.5.3构建 `MY_BOT_DISPLAY_BENCHMARK=OFF` 通过，ELF中无benchmark符号；app为0x1c3e70，2MiB分区余量约12%。USB烧录与串口版本回读通过，Wi-Fi重连成功；55秒采样的活跃秒帧率20–22、内部空闲最低54,983B、未捕获显示错误。这是当前皮肤短期采样，不能代替上面的三皮肤受控对照。[部署证据](../analysis/voice-throughput-evidence/deployment.json)与[设备采样](../analysis/voice-throughput-evidence/production-device.json)。主机服务仍为预热后的PID85548，同一原网关/隧道/配置。

实体麦克风、手势和首屏观感仍需用户实际操作确认；上述图像与行为检查不能替代这一项。烧录后额外一次自动回复为 **36.89秒**（客户端37.22秒首屏校验），其中通知接受→领取20.98秒、领取→收到reply13.58秒；六次样本整体范围23.00–36.89秒，说明云端波动仍明显。进一步减少需要云端执行策略或能力变化，本轮未擅自绕开原Bot的记忆与工具体系。
