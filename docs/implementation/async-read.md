# 点击已读后立即返回

固件 `0.13.0-async-read` 与语音服务 `0.3.2` 将已读确认移到后台。末页点「已读」后，圆屏先保存本地记录，再关闭阅读页；没有「正在标记已读」页面，也不等待 HTTP 返回。首页可继续按住录音或使用 BOOT。

暂时断网会保留确认并重试，重新启动后继续同步。本地尚未同步的消息不会重新亮为未读；查询信箱会跳过它们，让下一条回复仍可被发现。后台一次只执行一个请求，所以慢请求仍可能延迟下一条消息的发现。

本地最多保存 16 条未确认记录。存储失败或容量用尽时留在原阅读页，显示「保存失败」，保留内容和「已读」按钮供重试。新记录不挤掉旧记录。「稍后」仍不表示已读。实际加载回复的动画保持原样。

## 实现与约束

- 语音 actor 仍独占前台状态和 NVS 写入。新的 mailbox worker 只处理 Read 和空闲时的 Inbox；网络结束后释放自己的设置锁定状态，再交付可靠结果。录音期间暂缓处理需要写闪存的确认结果。
- 一个版本化 NVS blob 同时保存当前 pending 与未确认回执；本地已读通过一次更新加入回执并清 pending。Read(A) 的迟到响应只删除 A，不修改新录音 B。保存报错会核对实际读回值；这不等同于物理断电验证。
- Inbox 结果检查前台世代、journal revision、配置 epoch 和身份 scope。失败回执轮转，退避为 4–32 秒；到期 Inbox 在请求完成后有执行机会。
- 已认证的 `GET /v1/inbox` 接受可选 `X-Voice-Read-Exclude`：最多 16 个 32 位十六进制 ID，值最长 527 字节；重复头、畸形或超限返回 400。排除使用参数化查询，不改变远端 read 状态。仅 Inbox 的发送缓冲扩大到 2048 字节。
- scope 是带版本与字段长度的 SHA-256，输入为设备 ID、enrollment token、保存的 LAN CA。前台 Upload/Status/Retry/Page 与后台请求都用同一次凭据快照检查 scope。换信箱身份后，旧录音不会误投；恢复原身份可以重试。
- 保持 enrollment 的 LAN／公网路由被约定为同一权威信箱；协议不能识别复用同 token/CA 的另一数据库。token/CA 轮换会隔离旧记录，旧记录仍占总容量。旧版 pending 首次迁移按当前 enrollment 归属。降级到不识别新 journal 的固件可能重新显示未同步消息，应先完成同步。
- 未升级的后端会忽略排除头；新固件仍过滤本地已读的 A，但 B 可能等到 A 同步成功后才出现。因此本次先升级服务，再烧录固件。

## 验证证据

本轮基线为已部署的 `0.12.3-reply-animation`，工作区基于 `0b60829`，保留此前所有未提交功能。两份独立方案与独立评判选定上述结构；审核是同模型独立会话，不是跨模型审核。

| 检查 | 实际结果 |
| --- | --- |
| 原 actor 失败基线 | 卡住真实 Read 后仍处于 MarkingRead，无法回首页或开始下一次录音。 |
| 真实 actor + mailbox + journal | 17 个独立进程全部通过；Read/Inbox barrier 下 BOOT 和 hold 可录音，迟到 Read 不修改 B，旧 Inbox 不复活，多条回执、保存/删除失败及跨进程恢复通过。 |
| 真实 LVGL → 生产 actor | 末页按钮事件经真实 voice_action 关闭阅读层，Read 仍被卡住；保存失败标题可见、原页保留、再次点击可成功。截图中页面内容是隔离测试图；首页截图不含角色。 |
| Journal | ASan/UBSan，10 组、886 个断言；容量 16/17、幂等、迁移、损坏格式、NVS 错误与读回核对通过。 |
| 服务端 | 全部 101 项测试通过，包含 23 项真实隔离 HTTPS 排除协议检查；Read(A) 返回 503 时可查询 B/C，排除不写 read。 |
| 设置、传输与渲染 | core、remote、Wi-Fi、头像/阅读 UI 回归通过；2620 帧渲染比较、1800 帧语音角色比较、180 帧真实 LVGL 合成与刷新失败恢复通过。 |
| 独立审核修复 | 损坏 journal 启动时合法删除失败任务，避免 FreeRTOS 入口直接返回；旧录音更换 enrollment 后不再以新凭据上传。两项均有失败基线和修复后回归，审核者独立重跑通过。 |
| 构建与部署 | ESP-IDF 5.5.3 完整构建通过，benchmark OFF；USB 写入及哈希校验通过。55 秒回读 11 次版本正确，Wi-Fi 恢复，语音保持 Idle，无捕获到的 TE/Draw 错误；空闲/后台查询期间内部堆最低 43171 字节。设备状态与构建指纹见 deployment.json。 |
| 真实 LAN／公网 | 使用设备实际 User-Agent，0/1/16 项头与 527 字节边界均到达服务；畸形头均返回预期 400。此时信箱无未读消息，所以线上检查证明传输和解析；A/B/C 排除语义由隔离 HTTPS 测试证明。没有新建消息或标记任何真实消息已读。 |

Python 默认 User-Agent 曾被 Cloudflare 以 1010/403 拒绝，使用 SDK 源码中的 `ESP32 HTTP Client/1.0` 后通过；没有更改 Cloudflare 规则。此检查由 Mac 发起，不冒充实体设备完成了最大头发送。

[完整证据](async-read-evidence/deployment.json)包括测试日志、设计评判、最终审核、LAN／公网结果和设备状态。审核建议的三条测试旁白已删除，保留格式与 NVS 外部行为的必要说明。

实体触摸到退出的耗时、真实麦克风连续性、并行 TLS 的峰值内存、满 NVS 分区和物理断电恢复尚未实测。host 的 250 ms 断言只证明测试环境的响应，不是圆屏性能数字。设备启动与空闲查询正常，也不能代替这些实机验收。
