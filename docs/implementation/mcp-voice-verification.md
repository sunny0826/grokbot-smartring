## BOOT 无响应排查（进行中）

用户实际操作报告 BOOT 无响应，不能以此前编译和主机测试视为按键验收通过。
已烧录 `0.5.1-boot-diagnostics`，仅增加诊断，尚未判定原因或宣称修复。
USB `status.voice` 新增：`boot_pressed` 为当前电平，`boot_presses` 为去抖后按键次数，
`boot_queued` 为入队次数，`boot_handled` 为通过时效检查的处理次数。
`start_stage`：0 未启动，1 分配音频内存，2 初始化 codec，3 清理接收缓存，4 开始录音。
计数每次重启清零。诊断构建、核心状态与协议检查通过；等待监听期间的实体按键操作。

用户回复「按了」后读取诊断：监听最后一条为 09:02:37（UTC+8），此前 906 次
状态采样均未检测到按键；随后 USB 报 Device not configured。网关显示设备重新上线，
新的 uptime 从零计时。通过板载 USB-JTAG 读取复位寄存器 0x60008038 得到 0xf041，
两核复位原因均为 1（Power on reset）；诊断计数当前均为零。不能据此断言按键损坏
或软件崩溃，也不能把未捕获的动作算作按键验证。原理图中 SW2 为 GPIO0 对地按键，
尚待核对用户按键位置及当时是否掉电/USB 松动。

## 触摸按住说话（2026-10-17，当前入口）

用户确认之前长按导致关机，随后提出改为屏幕「按住说话」。按此选择实现并烧录
`0.6.0-touch-voice`：主页底部固定按钮，按住开始、松手上传、滑出取消；快速点按
不发送；录满 30 秒停录，等松手才发送。录音准备阶段单独显示，避免尚未采集就提示说话。
主页未读入口上移，两项操作互不遮挡。

手势使用独立 ID 与加锁的控制状态，松手/取消不会因界面状态更新或普通命令队列
满而遗失。开始前已松手则不启动录音；过期手势不能影响下一条录音。按钮在录音
过程中保持同一对象和位置，锁定触摸归属；取消后到松手前持续拦截触摸。

验证：C++ 手势状态、提前松手、取消优先、过期手势、30 秒边界检查通过；真实 LVGL
指针输入测试通过按住、松手、滑出取消、快速点按、弹出录音页后仍保持触摸归属、
宠物不误触，以及原有未读/分页/已读和整屏删除测试。已查看主页和录音页面渲染图。
ESP-IDF 编译和 app-flash 哈希验证通过，固件 1,468,944 字节，分区余 67,056 字节。
烧录后真实 MCP 确认固件 0.6.0 在线且 fresh；USB status 为 Wi-Fi 已连接、Idle、无错误。
