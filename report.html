本文整理的是视易（官方名 VIEWE / 优奕视界，账号 VIEWESMART）的 ESP32 触摸屏开发板资料；官方资料里没找到“视易”这个写法。

先按规格书型号找到单板仓库，再跑它自带的 Arduino + LVGL 8.4 示例；PlatformIO 现成工程也走 Arduino，ESP-IDF 要按板选版本，MicroPython 需要自己移植。

  • 名字先对齐。搜资料时用 VIEWE、优奕视界或 VIEWESMART；官网、规格书和仓库里都没有“视易”。
  • 规格书能公开读，旧示例地址会失效。用本文逐项表换到每个型号一个仓库，别只认仓库名前半段。
  • 主力是 S3。常见配置为 16 MB Flash + 8 MB Octal PSRAM；P4、C3 和无触摸旋钮另列，不能套同一组设置。
  • 先保留工程版本。VIEWE 示例锁定的版本比最新版旧很多，直接装最新版会遇到 API 不兼容，尤其是 LVGL v8/v9。
  • 可视化工具也要对版本。SquareLine 只有部分单板示例；官方更新记录没有写 LVGL 8.4.0 的支持，销售含该 UI 的产品需要商业许可。
  • 快验先找出厂固件。若目标是先检查屏和触摸，可先查对应仓库的 firmware；35 个 Gitee 仓库里没找到 VIEWE 的 MicroPython 固件、示例或教程。

1 名字和仓库怎么找

国内下载从 VIEWESMART 的 Gitee 项目页开始；用规格书完整型号确认仓库，旧大仓库地址已失效。

VIEWE 官网与技术资源中心使用 VIEWE / 优奕视界。Gitee 和 GitHub 同名账号对应这个品牌，X 帖子中指向 VIEWESMART 的仓库也可作为查找入口。SmartRing-Plus 中文 README 还出现过“微视显（VIEWE）”，这里统一称 VIEWE。

2026-10-12 07:49（上海时间），Gitee 用户接口返回 35 个仓库；VIEWESMART 是个人账号，不是组织。35 个仓库都能公开克隆。GitHub 同名账号有更多仓库，Gitee 用作镜像或同步入口，不能把两边清单视为完全相同。

1.1 按这个顺序对型号

  1. 抄下规格书完整型号，保留 -WB-A、-WB-B、MD80E、MD80ET 等后缀。
  2. 在仓库名里找尺寸与分辨率，如 80480043 或 4.3inch，再看 README 的型号行。
  3. 打开仓库的 information/ 或 datasheet/，以规格书 PDF 文件名中的型号为准。两块板分辨率相同，也不能省掉尺寸和版本核对。
  4. 进入该仓库的 examples/。先跑原工程，再替换 UI；若旧 PDF 地址返回 404，按下表找新仓库。

老款 UEDX… 的读法是对照规格书整理出的总结，不是官方命名规则：常见的 80480 对应 800×480、48270 对应 480×272、24320 对应 240×320；070、043 常对应 7.0、4.3 寸，E 对应 ESP32 系列，-WB-A 常表示 Wi-Fi、蓝牙与 A 版。旋钮常用 -MD50E、-MD80E，末尾 T 区分带触摸版。这套读法有例外，不能替代 PDF 核对。

只有新款 ESP32-S31 4.3 寸页面给了官方规则：PLCM 是 PCB + 显示模组，UE 是优奕视界智能显示模组，S31 是 ESP32-S31-WROOM-3，S043 是 4.3 英寸，H800V480 是 800×480，C 是 GT911 电容触摸，U 对应 UART / RS485 / I2C / CAN / USB。该新款在这 35 个 Gitee 仓库中没有对应示例。

3.3 PlatformIO

现成 PlatformIO 示例可以直接作为起点，但它们走 Arduino，多数用 pioarduino；“PlatformIO + ESP-IDF”没有现成 VIEWE 工程。

35 个仓库里共有 32 个 platformio.ini，其中 2 个来自非 VIEWE 板的仓库（用 native 和 LVGL 9），不算在内。其余 30 个板级文件里，26 个用 pioarduino 53.03.11 + Arduino core 3.1.1：25 个把 LVGL 锁在 #v8.4.0，1 个（1.3 寸 encoder13）用 release/v8.4 分支；另有 4 个用官方 espressif32 + release/v8.3 或 v8.4。这 26 个里有 3 个是 ESP32_Display_Panel/examples/platformio/ 下随库自带的例子，不是单板工程。

一句话：30 个板级 platformio.ini 中 26 个用 pioarduino 53.03.11 + Arduino 3.1.1，LVGL 多为 v8.4.0（1 个用 release/v8.4）；另有 4 个用官方 espressif32 + release/v8.3 或 v8.4。7 寸的关键配置如下，其他型号保留自己的 board：

platform = https://github.com/pioarduino/platform-espressif32/releases/download/53.03.11/platform-espressif32.zip
framework = arduino
board = BOARD_VIEWE_UEDX80480070E_WB_A
  1. 按 PlatformIO 的 VS Code 文档安装环境。
  2. 在单板仓库的 PlatformIO 示例中找到 platformio.ini，以这个工程目录打开，保留仓库带的自定义板定义。
  3. 检查 platform、framework、board 与依赖：多数工程的 Arduino core 锁在 3.1.1，LVGL 锁在 lvgl.git#v8.4.0（也有 release/v8.4、release/v8.3 的）。不要先替换为官方平台或未锁版本的库。

官方文档入口：Espressif32 平台、Arduino 框架、ESP-IDF 框架、LVGL 集成。LVGL 文档中的 lib_deps = lvgl/lvgl 是通用写法；复现 VIEWE 老工程时继续使用原来的 v8.4.0 锁定项。

若自行搭 ESP-IDF 工程，配置改为 framework = espidf，工程根目录用 sdkconfig，通过 menuconfig 目标修改。PlatformIO 官方文档写每个平台版本绑定特定 IDF，最新平台支持最新稳定 IDF；先检查所选平台是否满足板上 BSP 的要求。官方板列表没有 VIEWE，官方 platform-espressif32 v7.1.3 与 Arduino-ESP32 3.x 的具体关系未核实。

3.4 ESP-IDF + LVGL

需要细调驱动、PSRAM 和性能时，用本板的原生 IDF 工程；先确认 README 的 IDF 版本和组件文件的 LVGL 版本。

仓库README 写的 IDF特别要看
1.9 寸、2.1 寸旋钮、3.5 寸 320×480、早期 SmartRingV5.1 / 5.2 / 5.3这些是 README 列出的版本，不能理解为任意新版都能用。
2.4 寸、2.8 寸、5 寸、7 寸 S3、SmartRing-Plusv5.3+7 寸、2.4 寸、2.8 寸的英文 README 写 v5.3+，中文 README 写 V5.1 / 5.2 / 5.3，以你实际打开的那份为准。仍需看该工程的组件依赖，不能与 Arduino 的 LVGL 8.4 混装。
4.3 寸 800×480、4.3 寸 480×272v5.5+新 BSP 要求这个版本；旧规格书中的 IDF 示例地址已过期。

组件文件里也不统一：P4 系列多见 lvgl/lvgl 9.2.*，小智圆屏有 ~9.2.2，SmartRing-Plus 小智有 ~9.4.0；1.3 寸旋钮与 EMO-Dot 的部分旧工程为 ^8 / ^8.3.0。P4-Pi 同时有 08_lvgl_demo_v8 与 09_lvgl_demo_v9，选一个工程运行。

  1. 安装所需 IDF。单板 IDF README 要求 VS Code 的 Espressif ESP-IDF 扩展；4.3 寸中文 README 写通过 EIM 安装。按上述版本表和所选目录的 README 配置环境。
  2. 打开一个独立工程。4.3 寸 800×480 有 8 个 IDF 工程，480×272 有 6 个；5 寸有 lvgl_v9_demo_5inch、squareline_coffee_5inch、gui_guider_monitoring_5inch、sd_card_spi。先从扫描 / 基础显示示例开始，再运行 UI。
  3. 保留 BSP 与组件版本。4.3 寸新工程使用 ESP 组件注册表的 BSP，800×480 对应 viewesmart/bsp_uedx80480043_wb_a，通过 bsp_display_start() 起显示。先检查板上 WB-A / WB-B，不只凭 BSP 名字决定（仓库 README 写着软件上没有区别）。
  4. 检查 PSRAM。在 menuconfig → Component config → ESP PSRAM 开 CONFIG_SPIRAM，S3 的模式选 Octal。4.3 寸新示例的 sdkconfig.defaults 已设置 PSRAM、16 MB Flash 与 CONFIG_LV_USE_CLIB_MALLOC 等项目；先保留这些默认项。
  5. 编译、烧录并观察日志。用 README 指定的扩展环境操作，按本板下载模式烧录；先确认屏、触摸，再改 LVGL 配置。需要保留的配置写回 sdkconfig.defaults。

自行新建工程时，LVGL 官方 IDF 集成文档给出下面的依赖添加方法。现成 VIEWE 工程已有依赖时，不要再加一个不同版本。

idf.py add-dependency "espressif/esp_lvgl_port^2.3.0"
# 下面是新建 v9 工程的版本约束示例；不是 v8 工程的升级步骤
idf.py add-dependency "lvgl/lvgl^9.*"
idf.py menuconfig

esp_lvgl_port同时支持 LVGL 8、9，文档要求 IDF ≥ 4.4；这不降低 VIEWE BSP 的 5.5+ 要求。显示与触摸由 esp_lcd、BSP 中的 esp_lcd_* / esp_lcd_touch_* 组件处理。调用 bsp_display_start() 或 lvgl_port_init() 后，LVGL 在后台任务运行，不用再自己调用 lv_timer_handler()。

官方说明：S3 外部 RAM、RGB LCD、LVGL 组件、LVGL ESP32 性能技巧。RGB 帧缓冲可设 fb_in_psram，文档也说明 bounce buffer 和双缓冲防撕裂。

场景官方文档中的选项限制

3.5 MicroPython + LVGL：自己搭的起点

还不能把它写成 VIEWE 的现成快速验证路线：没有单板固件、示例、教程，也没有本报告的上板验证。

35 个仓库中只有 SmartRing-Plus README 一句兼容 MicroPython，以及教程目录中的一张 MicroPython logo；没找到完整开发路径。SmartRing-Plus 带的 ESP32_Display_Panel 1.0.4 有 micropython.cmake、mpy_support，也没有 VIEWE 板使用教程。

MicroPython 官方 S3 固件提供 v1.29.0 的 .bin / .app-bin / .uf2，也保留 v1.28.0；它是纯 MicroPython，不含 LVGL 绑定。装好它不等于屏幕可运行 LVGL。

  1. 先选绑定项目。LVGL 官方 MicroPython 文档将它用于快速原型：固件和驱动备齐后，在 REPL 改 UI 可省掉反复编译烧录。官方分支是 lvgl/lv_micropython，README 把用法指向 README-LVGL.md。
  2. 若选分叉，按分叉的说明编译。lvgl-micropython/lvgl_micropython 是另一个、主要由个人维护的项目。2026-10-12（上海时间）读取的 README 要求 Python ≥ 3.10，支持 Linux / macOS，Windows 编译标为 not yet supported；不要用官方绑定的构建说明，不要在克隆后手工初始化子模块，要更新则删除后重克隆。这是该项目写的限制，本文未验证它在 VIEWE 板上的构建。
  3. 逐一核对屏与触摸 IC。分叉的列表含 GC9A01、ILI9341 / 9488、ST7789、ST7796、SSD1963，ST7701S 标 WIP；触摸含 GT911、CST816S、FT6x36。VIEWE 的 GC9307、CHSC6540、CHSC6413、CST826、CO5300、ST7262 / ST7282、GC9503V、JD9165BA 未找到现成驱动。通用 rgb_display 也不能代替板级初始化。
  4. 补板级初始化。S3 的 ESP32_GENERIC_S3 + SPIRAM_OCT 能对应 8 MB Octal PSRAM，但还要自己处理引脚、背光、IO 扩展器和触摸复位；VIEWE 没提供这些 Python 初始化。
  5. 构建、烧录后才开始交互改 UI。下面仅是分叉 README 的构建形式，屏驱动为 ST7796、输入为 GT911，不是任何 VIEWE 型号的已验证命令。可按该项目说明加 deploy PORT=… BAUD=… 烧录。
python3 make.py esp32 BOARD=ESP32_GENERIC_S3 BOARD_VARIANT=SPIRAM_OCT DISPLAY=st7796 INDEV=gt911

该分叉 README 写 MicroPython 只用一个核；RGB 驱动用局部缓冲加第二核搬运，帧缓冲必须在 SPIRAM，绘制缓冲建议约为屏幕的 1/10。以上为 2026-10-12（上海时间）读取的项目说明，本文未验证；不要把它理解为所有框架的统一内存安排。

该分叉许可证页面显示 Other / NOASSERTION，没有明确 SPDX。SquareLine 有 MicroPython 模板和 LVGL9 导出相关记录，但它与 VIEWE 板的衔接没有资料可照做。
